# 原生骨骼与六关类肉鸽实施计划

2026-10-09，目标active，无指定token/时间预算。用户授权美术自主裁决，不重复等待A/B/C；方案与验收以 [规格](../docs/campaign-skeleton-spec-v1.md) 为准。每个已验证小步聚焦提交并推送，旧可玩包/存档和无关脏文件保留。

## 实施顺序

1. **M0：把关卡与波次分清。** 建立六关目录、顺序Boss解锁模型和独立永久进度store；旧RunSnapshotStore不冒充关卡进度。先完成测试与契约，不把未完成系统暴露成六关试玩。
2. **M1：原创风格与骨骼样板。** 免费参考清单→玩家/普通敌怪/大型敌人静态样板/紧凑效果的最小风格锁→一只小怪真正骨骼动态样板。自主审查轮廓、关节与原生性能；大型样板此时不做攻击动画。
3. **M2：开始页与第1关纵向闭环。** 新开始页和六关地图选择→1关随机布局/遭遇/奖励→Boss结算解锁、重新进入第2关与永久保存。所有过程可返回、可失败、可重复；只有实际接入才算可玩。
4. **M3：全套新骨骼与普通动作。** 玩家四朝向和各类小怪逐一制作/接入；六区敌族及六Boss拆件、骨骼、非攻击动作、挂点；背景与UI配套。每个角色3至5个源/场景/测试文件独立交付，不一次堆几十个未验收资源。
5. **M4：骨骼齐备后处理大型攻击。** 确认全角色骨骼资源门通过，再制作大型敌人/Boss攻击，逐招校对预警/实际命中/取消/死亡，不增加隐藏重复伤害；同步重做其他动画效果。
6. **M5：六关差异化与类肉鸽循环。** 每关独立地图规则、敌族/攻击、Boss阶段、风险奖励路径；完成一关再推进下一关。增加可重玩的构筑/事件选择，不用不必要刷数值代替长期趣味。
7. **M6：全链验收与本机交接。** 完整六关、解锁/死亡/重玩/存档跨进程、不同种子、密集渲染、输入/退出/返回、许可与实际PCK证据；真人手感独立待确认，保持不发布。

## 门禁和风险

- 原生样板确认实际骨骼与四肢相对运动，不能只展示资源文件数量或头部整体摇摆。
- 先有角色风格锁再批量产出；用户授权自主决定不等于任何失败资产自动final。记录自主批准/许可核验/原生证据各自状态。
- 原来6波不能直接重命名为6关；每关需Boss、独立地图/敌族、解锁与重玩。
- 大型攻击延期依赖明确：全套骨骼资源门通过之后才能开工，不被M2“需要Boss”悄悄绕过。
- 旧保存数据与新永久解锁分开；不读取旧波次字段给新关卡开锁，不覆盖/删除用户旧档。
- 分层素材不是自动生成动作。缺失遮挡部件、关节余量、朝向要补制；免费素材也逐包核对许可。新第三方MCP/运行库安装另行确认，原生文件/CLI无需MCP即可推进。
- 通用技能的definition-of-done附页在本机缺失；采用规格里的明确完成条件与现有严格测试入口，不借模板缺失跳过验收。
