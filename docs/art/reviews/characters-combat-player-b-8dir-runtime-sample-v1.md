# 玩家 B 方案 8 向 64px Godot 样片评审 v1

## 评审状态

- 状态：`preview`，等待用户评价；不是 `gameplay-approved` 或生产资源。
- 目标：在不接管正式 `Player.gd` 的隔离板中验证 45°相机、真实前/侧/后转身、身体/枪械分层、Alpha、64px可读性和pivot。
- 捕获：`docs/art/previews/characters-combat/player-b-8dir-runtime-board-v1.png`。

## 运行板四行含义

1. 青色标记：8个方向的64×64合成参考，保持实际游戏尺寸。
2. 洋红标记：身体层放大1.5倍；双手保留射击握姿，枪械已移除。
3. 橙色标记：同方向枪械层放大1.5倍；正面和背面有明显缩短，不是侧视贴图平面旋转。
4. 白色标记：Godot现场分层合成；青色圆为现有13px碰撞半径，白色十字为固定pivot。

## 通过项

- 0°/90°/180°/270°分别呈现右侧、正面、左侧、背面，四个斜向也可区分。
- 身体、枪械和合成参考都由同一8向序列切片；运行时不调用单张侧视枪旋转。
- 三条图集均为512×64 RGBA，24个单元非空且透明角通过。
- Alpha `<32` 已清零，`>=224` 已固化为255；主体没有旧Shader造成的整体半透明。
- pivot固定在64×64帧中心，和现有13px玩家碰撞圆重合。

## 尚未通过/生产前必须修复

- 当前只有8个45°关键方向和一个静态射击姿势；尚未扩展到方案B的24向或idle/run/fire/dash/hit动作。
- 样片的枪械遮挡仍按方向把整枪放到身体前或后；正式资源必须输出精确的`weapon_behind`和`weapon_front`蒙版，避免手掌、枪身和背包互相穿插。
- 握持点和枪口点尚未形成24向socket元数据表；正式接入前必须自动验证每帧存在且位于64×64画布内。
- 图像生成带来的少量盔甲细节漂移只能作为方向/尺寸样片，不能直接扩展成生产动作帧。

## 下一门

用户认可这张64px实机板后，先完成一个方向的idle/run/fire/dash/hit垂直切片和精确前/后枪械蒙版；该切片在实际战斗场景通过后，才扩展到24向。
