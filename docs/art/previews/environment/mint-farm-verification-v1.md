# 薄荷实验农场：移动与密集战斗验证 v1

基线采集：2026-09-08；文件与截图复核：2026-09-13。基于游戏提交 `a7fb4a0`，本轮只新增验证工具与证据，不修改游戏行为，不发布版本。

## 结论

地面整数位移采样与密集战斗工具检查通过；密集战斗视觉可读性尚未通过。截图中玩家被敌群、叠加特效和血条淹没，不能把工具输出的 `BENCHMARK PASS` 当作美术验收通过。

## 方法与结果

- Godot 4.7 stable，RTX 5060 Laptop GPU，1280×720，单机调试运行。
- 固定地图种子 20260908；初始 80 个真实 AI 敌人，验证至少一个敌人实际移动超过 4 像素。采样期间敌人数 61–80。
- 玩家固定、无敌，脚本移动相机并周期性发射子弹和生成火花；不是人工移动、碰撞或完整局试玩。
- 240 帧预热，1200 帧采样；测量相邻 `process_frame` 的墙钟间隔，平均 4.760 ms、P95 8.388 ms、最大 11.456 ms。采样总时长约 5.71 秒，不代表显示器呈现帧率或长期稳定性。
- 监视器最大绘制调用数 337，弹体节点数峰值 149，纹理内存约 21.86 MiB。引擎监视器数据不等同于独立 GPU 分析。
- 地面相机位移 (1,0)、(32,24) 后比较同一世界位置的 RGB，最大通道差 0。仅覆盖这些整数位移和采样区域，不证明亚像素运动、缩放或所有接缝均无闪烁。
- 采集阶段 Godot 导入通过，Python 74 项测试通过；本轮未重新执行完整游戏 Godot 测试集。

初次尝试因波次横幅未结束而触发暂停，结果作废。最终脚本先结束横幅，并在每帧检查未暂停、仍处于 PLAYING；AI 没有实际移动时失败。正式报告不采用不一致的旧进程耗时监视器数据。

## 复现

在 `5分钟超载` 工作树执行（`godot` 替换为本机 Godot 控制台程序）：

```powershell
godot --headless --path . --import
godot --audio-driver Dummy --path . --script res://scripts/art/BenchmarkMintFarm.gd --quit-after 2400
python -m unittest discover -s scripts/tests -p 'test_*.py'
```

渲染基准不能使用 headless。运行会覆盖本目录的 `mint-farm-benchmark-v1.json` 与 `mint-farm-stress-v1.png`；只使用并清理专用 `user://mint_farm_benchmark_test.json` 存档，不应与另一实例同时运行同一基准。

## 下一阶段与验收边界

1. 优先修复玩家在敌群中的定位可读性；检查玩家轮廓和局部遮挡处理，不以全局置顶破坏障碍物前后关系。
2. 控制装饰性命中特效叠加，保留真正伤害范围、危险弹体和攻击预警；区分血条优先级，避免信息堆叠。
3. 在相同压力场景及真实移动穿障碍场景对比截图，再进行完整局与较长时间测试；不能仅凭单张截图或高帧率验收。

保持已批准的 B 方案、纯 2D Q 版与每局随机地图。以上是后续修复方向，尚未实施；若引入新的视觉风格，仍需先提供预览审批。环境资源继续标记为草稿。
