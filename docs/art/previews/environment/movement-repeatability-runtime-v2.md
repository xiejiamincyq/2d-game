# S1-B：逐物理步真实输入与双轨测量

2026-10-03，`5分钟超载`，非发布。用户已取消网页端监督；本阶段由工作区证据及独立审查判断。这里只验收测量基线，不把它叫作平衡、美术、人工试玩或全项目完成。

## 复现与改动

旧工具使用 `await physics_frame → await process_frame`。实跑 `--headless --audio-driver Dummy --max-fps 30` 的 `realtime-red-30-01`：只记录1条样本，却经过2个物理步、移动7.8333px；标记无效，未放宽检查。

新 `MovementPhysicsSampler.gd` 使用物理优先级前后两次回调：输入和鼠标事件先于玩家回调，状态采样在游戏节点物理回调后。每条记录核对同一个连续物理步、两次delta、实际输入与瞄准。渲染帧可以包含0至多个物理步，不再假设一一对应。其优先级机制参见[Godot Node 文档](https://docs.godotengine.org/en/stable/classes/class_node.html#class-node-property-process-physics-priority)。

终止先封存状态和墙钟，再同步交回SceneTree所有者冻结，避免同一渲染帧多走一步。死亡发生在输入前则不伪造样本；发生在回调期间则标明最后一步瞄准未认证，其他步仍严格检查。非死亡意外暂停判无效。截图等待前封存反馈事件，诊断清理不冒充自然顿帧恢复。超时改为真实60秒，不受渲染帧数影响。

健康/护盾按信号累计实际下降，能保留治疗后再次受伤。所有改动限于诊断脚本，没有修改正式Player、敌人AI、伤害、碰撞或技能时序。

## 矩阵合同与复跑

三种子20260908/09/10 × walk/dash × 三重复 × D/R = 36个预注册槽，独立进程，先D后R，每槽1200步或真实死亡。两轨都按真实节奏运行，D仅压制hit-stop，R调用正式反馈；不开固定帧或电影加速，不逐帧重置敌人。Dummy音频及headless不提供实际声音或视觉性能验收。

```powershell
python -B scripts/art/run_movement_repeatability_matrix.py --godot <本机Godot控制台exe> --batch <未使用的批次名> --headless
```

启动参数、源码前后SHA、退出日志、JSON摘要及逐步轨迹保留在 `build/diagnostics/movement-repeatability/`。每次使用新批次名，拒绝覆盖或挑选性补跑。完整矩阵结果与来源哈希以本页后续实测记录为准。

`wall/unscaled-step`在0.9—1.1内只是外部启动记录配合实测节奏的一致性门，不是仅凭报告自动认证时钟；原报告`real_clock_pass`保持false。1200步是20秒未缩放步预算，R的累计游戏时间可能更短。三次首个轨迹分歧照实报告；敌人仍依赖墙钟/实例ID，不宣称确定性。

低进展指标定义为沿输入方向移动少于普通行走速度×该物理delta的10%，累计模拟秒；冲刺时也只是行走等价值参考，不是冲刺预算或“卡死”裁决。60AI夹具关闭自然导演且一次摆入环形敌人，不代表正常关卡、整局或S2平衡。
