## 测量修正与回归保护

初版在 `physics_frame` 信号处读取位置，该信号先于节点物理更新。
紧接着等待截图时，仍可能发生一次移动，而下一轮重新取起点会漏计这段路程。
此前口头报告的 212 / 287 像素，以及旧时序重跑的 296.811 像素，均不作为有效门槛依据。

修复前先加入“截图等待期间位置不得变化”的断言，并在空场第 120 步、移动输入仍按住时触发截图读取。
旧版稳定报告 `capture skipped player movement`；修正后该回归检查通过。
当前统一在物理信号后等待 `process_frame`，再读取完成物理更新的位置；截图只等待随后同一帧的绘制。
同时核对三阶段的引擎物理步数差，避免截图引入漏步或额外步却仍称作固定样本。

独立只读审查确认：采样修正、轮廓触发门槛和存档隔离无剩余提交阻塞。
最终命令非零退出是因为普通移动诊断下限未通过，不是引擎、脚本或着色器报错。

## 复现

在本分支工作目录，把 `godot` 替换为本机 Godot 4.7 控制台程序：

```powershell
godot --headless --path . --import
godot --audio-driver Dummy --path . --fixed-fps 60 --script res://scripts/art/VerifyMovingReadability.gd --quit-after 3000
python -m unittest discover -s scripts/tests -p 'test_*.py'
```

脚本成功写出报告时，`scripted_checks_passed` 要求路程下限、轮廓触发和帧数完整性都通过；否则 `needs_review` 并非零退出。
无效场景、穿透或截图失败会报错并提前退出，此时不能沿用旧 JSON 作为新结果。
