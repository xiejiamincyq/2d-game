## 结构、契约与开放问题

旧永久章节档只读保留与迁移。新旅程是单一原子提交文件，统一保存金币、继承卡等级、单调已领取通关序号及待领取奖励；新解锁从已领取序号派生，避免两档写入产生半成功。独立于旧波次文件。六关序号计算轮数与下一关，状态不随轮次无限膨胀。严格版本/整数/卡片/前置验证，失败不修改原状态。详见 [存档契约](campaign-session-contract-v1.md)。

默认每次有效通关仅继承所选普通卡一个等级；不携带整局构筑、流派等级或终极。重玩可以得到/消费金币但不反复领取同轮同关奖励。附属卡只有前置已继承才可选，提示原因，不授予无作用奖励。失败不授予通关奖励；返回帐篷保留余额与已继承能力。

用户已批准：第六关返回帐篷后继续进入下一轮第一关，重玩仍是刚完成轮次第六关，不重复发继承奖励。无需等待该问题。赛车误贴排除，不再处理R1/R2。

### L1初始增长与容量规则

第一轮原遭遇配置不变。后续每轮按第一轮基数增加25%总量（向上取整），敌方生命按第一轮基数每轮增加35%，包括Boss和真实分裂/孵化子体；不提高移速、伤害或缩短攻击预警。每轮解锁一类已有异区敌人混编，原区域仍占多数；不把母孢/种植者跨区移植，以免绕过其专属出生事务。有限已实现角色池全部解锁后不制造假“新种类”。单遭遇总量最多144，存活/待出生预算48；母孢预留两份碎体位置，孢囊预留一个子体。达到容量时传送门等待空位，不丢弃清场债或积累恢复后的瞬时补生。数量和种类到安全/实际资源上限后不再无限堆叠，生命继续递增；该边界是性能约束，不宣称无限新增种类。

### T1共用陷阱管理器契约

`ReusableTrapField`拥有公共`ReusableStepTrap`，六关正式区域场景共用该机制；单测本身不代表接入或完整验收。`configure(layout, seed, player=null, count=10) -> bool`只布点、不启动；数量限定0–16。布局无效或无法找到全部请求数量时返回false，保持关闭且不留下半套危险。重新configure代表新布设；单纯启停/重新绑定玩家不重置生命、不补生已摧毁单位。第二关普通/风险启用10/16处，其余五关2/4处；全部布点在INTRO已存在，关闭时灰绿、授权时青绿、踩踏短预警橙圈，冷却暗色，80HP血条可见。暂停冻结计时，不将旧周期陷阱的强制重置冷却当成新踩踏机制。

`get_sites()`返回布局局部坐标的副本；配置时支持管理器和地图已有的平移旋转，孩子世界位置等于`layout.to_global(site)`。正式地图为静态地形，不承诺配置后单独移动管理器/地图的动态重新锚定。候选需通过66px普通移动撤离空间、出生/Boss缓冲区及正常玩家半径可达检查，彼此至少170px，不改建筑描述符。布点用局部种子RNG，不污染全局随机数。

`bind_player`先取消旧预警再换引用；`set_active(value,count=16)`受真实玩家/布局存活限制，激活由章节导演授权。暂停冻结孩子，玩家死亡/退出、布局退出、管理器退出立即取消危险。`get_destructible_targets()`只返回自己尚存活的地形单位，不访问全场景敌群、不制造击杀/通关债。`clear()`退组和断开连接，不遗留生效的孩子。

孩子入树会同步触发外部回调；回调清理或撤出布局后，外层配置必须返回false、不再绑定玩家。嵌套`configure`显式拒绝，内外两次调用均失败并关闭整套布设；不支持回调内创建第二代配置。取消后可在正常调用栈重新配置。

`scripts/systems`：公共旅程/保存/继承；`scripts/campaign/ChapterRun.gd`：六关唯一协调；`scripts/ui/ChapterRunUI.gd`：结算。共享地形生命和伤害组件，不把建筑列入敌人事务。`scripts/tests`：行为回归；`docs`：审查证据；`tasks`：进度。
