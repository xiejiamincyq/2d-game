# 实际导出 EXE 普通窗口输入验证 v1

2026-10-07，仅补独立程序的真实输入证据，不修改正式游戏、不批准发布，也不勾选 S2—S5 整体。

## 对象与隔离

使用[交接 v4](local-playtest-handoff-v4.md)保留目录中的实际 `five-minute-overdrive.exe` + PCK；启动前逐字节大小/SHA256匹配交接记录。不是编辑器引擎代跑：EXE SHA256 `b5972ed3389906d857e60315308e18d3474bab4eeaa3a32a00bf637643cfc4d0`，PCK `16fec82c223d4f7725b150e7448ede3bda082836a8c78e621bc6c5d43d051f8e`。

仅给子进程设置新的 APPDATA，命令附加 `--audio-driver Dummy --resolution 1280x720 --log-file …`。没有 `--script`、`--path`、作弊、改包或新增正式调试入口。[Godot 4.7 Windows 实现](https://raw.githubusercontent.com/godotengine/godot/4.7/platform/windows/os_windows.cpp)从进程 APPDATA 派生数据目录；实际存档和缓存也出现在此隔离目录。六个正式/测试存档路径运行前后均 absent；20个原有脏文件逐hash不变。

实际程序正常输入无法由无外部脚本能力的发布模板注入完成，因此按 Computer Use 技能操作唯一返回的游戏窗口：每次一项输入后立即重新观察，只归档游戏窗口，不保存其他应用清单或桌面画面。诊断辅助源是本次一次性测量脚本，不是新增生产控制器；原路径 `scripts/art/` 中的两个本次新文件已移至忽略的本次诊断目录 `source/` 保存，未删除，不作为可复用工具交付。

## 实测范围

| 普通输入 / 观察 | 结果 |
| --- | --- |
| 开始按钮 | 正常进入第一波；新局瞬间 HUD 错误显示旧占位 `1/8`，随后实际状态更新为 `1/6`，瑕疵仍待修 |
| 不移动、不射击的自然首局 | 约10秒死亡，结果页 HP0、抵达1/6、击杀0；先前 Space 输入发生在已死亡结果页，不能计为暂停通过 |
| 死亡后 R | 返回标题页，不跳波、不锁血 |
| 第二次开始后 Space | 进入战术暂停，HP94、用时00:03；相隔13.833秒两次原JPEG字节/hash完全相同 |
| 暂停页继续按钮 | 退出模态并恢复战斗，下一原图 HP86；不是完整运动/射击测试 |
| 普通 Alt+F4 | 精确被测进程 PID15888 真实退出0，未触发900秒看门狗；但console.log有2个ObjectDB实例泄漏警告，干净退出门失败。wall373.457秒包含操作与暂停，不是战斗时长/性能测量 |
| 再次启动同一EXE与隔离目录 | 新进程 PID39816 显示可用继续按钮，点击后恢复第一波开场，HP100、金币0、用时00:00、1/6剩余41；再用Alt+F4，保留的PowerShell Process返回退出0。仅resume-engine.log没有错误；第二进程未归档控制台，不能证明无泄漏 |

第二个进程读取的是第一个EXE按正常流程自己生成的 `wave_intro` 存档，不是合成或编辑器复制来的存档。前后观察 `map_seed=4069775045`、生成器2、pending_stage1；该合同恢复稳定开场边界，不是退出瞬间HP86/敌人动态位置续接。继续时开场会重新序列化存档：已现场读取hash由 `9930d54c96450ab32234f5dbf32e0df59bac62aa272ca9724adbe000c82f4091` 变为 `6f5ada9f388fd5def80d895988c4a1007006cc4825453e25fe53a3adca1981f4`，家庭等级整数被读回并写为浮点数；不宣称文件字节不变或全地图逐障碍比较。原存档及缓存只留本机，包内只有衍生摘要中的观察事实。

## 证据与边界

[证据包v2](exe-window-input-evidence-v2.zip)：18成员（17数据+索引）、392492字节，SHA256 `dddf37dae09d8eb4cd89e7c0a79927e5c5356fff2cf19e3f60d65a9c929731ce`。8张原始有界JPEG、观察时间/窗口身份/hash、原日志、启动事实、一次性辅助源及衍生关闭摘要；CRC、全部成员大小/hash、源到包字节相同已核对。未包含用户存档、GPU缓存或其他窗口。`closed-summary.json` 明确是原本机关闭记录的筛选副本；第二进程退出码来自直接读取Process对象的现场结果，没有虚构原始终端日志文件。

独立审查指出初版launcher仅扫描engine.log，原closed.json的`errors=[]`漏掉console.log警告，初稿“无泄漏”结论撤回。原日志/关闭记录不改，失败v1归档移到忽略的本机诊断目录保留；v2显式列出`console_forbidden`与`clean_exit_gate_passed=false`。封包完整性成功不等于游戏干净退出通过。退出泄漏根因尚未确定，须继续定位而非压掉警告。

本证据片没有生产代码变动，没有声称重新跑全套回归。真实EXE普通窗口开始/死亡/R/暂停/继续/第一波跨进程读取/退出0有证据，但干净退出门未通过；完整六波结算、商店、Boss、胜利、持续WASD/射击/冲刺、实际听感、GPU呈现性能和人工手感仍未由本片证明。下一片复现并修开场HUD假总波数、定位退出泄漏，再刷新本机交接；整局EXE证据仍保持待完成。
