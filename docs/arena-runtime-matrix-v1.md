# 20张随机地图：真实碰撞、生成与四向往返验收

2026-10-04，分支 `5分钟超载`，生产基线 `ee2a15549add3851177724d88513933aecaadb9c`。本片只增加隔离诊断、外部核算和回归；不改地图生成器、碰撞、玩法或已批准美术。不使用网页监督，不发布。

## 结论与范围

预注册20个初始RNG种子 `2026100401—2026100420`，通过正常 `Main._begin_run({})` 新游戏路径产生20个互异实际 `map_seed` 和20种顺序无关的地形布局。最终 headless-v3 和 native-v3 均完成并退出0；每组230个真实障碍扫掠、160次七类敌人/Boss实际生成、60个真实第一波传送门、160段四向往返路线、36,766步真实Player/Input记录通过外部核算。实际圆形身体半径16.9px、速度235px/s；每图1832—1895步，最长单程326步。

这个结论是**隔离地图运行时验收**，不是20局自然通关、敌人AI/拥挤脱困、正常相机视觉、人类手感或性能验收。夹具冻结战斗导演、敌人AI与传送门计时；玩家路线仍执行原 `Player._physics_process` 与真实碰撞。四个目标为世界左/右±1120、上/下±680，独立64px栅格BFS使用实际注册的碰撞矩形，目标落在邻近格心（距指定目标≤48px），每方向到达后返回中心邻近格。不是证明世界每个可走点都已实际踏遍。

## 核查方法及结果

- 隔离存档路径在任何Main开始前指定。两组各六个真实存档路径及其tmp/bak前后均absent；未清除用户存档。两组orphan均0→0。
- 逐个读取真实 `CollisionShape2D` 的全局矩形，与描述符对照。最大坐标舍入误差约 `3.0517579e-5px`；显式允许 `1e-4px` 数值误差，不是扩大碰撞形状/允许像素级穿透。后续寻路与外部几何检查使用实际矩形。
- 每障碍使用真实Player的 `move_and_collide(..., test_only=true)`：记录起点、终点、motion、travel与对应真实collider，230项全部匹配。探测及路线开始前允许明确定位夹具Player；连续路线内不传送、不改速度/血量/碰撞、不直接调用运动函数。
- 七类Enemy和Boss通过实际Director从障碍中心申请生成，每图8次；记录实际位置、半径及共享navigation绑定，再独立核对圆形身体不嵌入地形/不越界。这里不是自然敌人移动或视觉图片包络验收。
- 传送门采样前Player恢复正常中心 `[0,0]`，固定独立spawn_rng，然后调用真实第一波开启路径。每图3个门，最小玩家间距约359.999978px、最小同批间距170.032893px，满足260/160px合同及48px地形安全圆。
- 每一运动步留存before/after、实际Input、计划Input、delta及绝对physics帧。外部检查连续位置/每图逐帧完整性、非零且一致输入、最大速度步长、世界边界、身体不嵌地形与到达目标。没有把端点检查称为独立完整线段扫掠或所有物理情况的CCD证明；真实物理执行与逐墙探测是另外两层证据。
- 两组地图、几何、生成/传送门及全部非frame路线字段逐项完全相同。地图索引i=0…19的native绝对physics帧比headless统一多i：每张原生overview额外经过一帧。**原始路线字节不完全相同**，未人为改写帧号对齐。
- 两组各14份选定源码运行前后与当前文件、source-v3冻结副本SHA一致。范围不是全部依赖闭包；例如FloorGrid、美术图及全部UI/effects并未加入这14份快照，ZIP不可作为可运行游戏重建包。
- native-v3额外20张真实地图概览均1280×720、哈希匹配、非平坦且互不相同。概览统一0.4倍缩放、隐藏HUD，只为看完整地形，**不是正常试玩镜头**。实际抽看00/04/09/19等原图；未冒称人工逐张/整段视觉验收或像素级地形配准。
- headless-v3生产者112089断言、native-v3 112109断言，多出的20条恰为概览检查，不是额外玩法覆盖。全量门63 Godot套件169685断言、29 Python套件191测试退出0；13个新核算器测试在其中。独立只读审查最终v3未发现Required/Critical。

## 没有丢弃的失败与修正

1. 核算器模块不存在的首次红测退出1；实现后逐步补反例。smoke-v1把全局变换浮点值作精确数组比较而失败；保留失败并增加“3e-5舍入可接受、0.01px偏移拒绝”的红绿回归，未扩大生产碰撞。
2. smoke-v2只测障碍、v3加生成/门、v4加连续输入，均不是完整20图通过。初版v1门在最后一个障碍探测位置开出，而不是正常中心：v1两组虽然生产者valid=true，仍不满足最终门语义。独立审查发现后复位中心并增加玩家/门间距与同批门间距检查，完整重跑。
3. 独立审查推动4个真实红测：零输入却移动、重排同一几何充当另一地图、Python `-O` 去掉assert、非中心/过近门。改为显式require、顺序无关布局签名、非零输入、中心出生及门间距检查；另补中心几何安全。最终13个单测通过，合成unit fixture不计入实际20地图。
4. native-v1写出20PNG，但索引00/01/04/09/12/17为平坦黑图。默认SubViewport可见时更新不可靠；仅修改诊断截屏，强制UPDATE_ALWAYS并增加图像变化检查。真实一图原生调通后，重新登记v3并完整重跑headless/native。原生v2未启动，不杜撰其结果；headless-v2被后续capture源码版本替代，不作为最终当前绑定。
5. `native-v1-final-check-rejected.json` 保留旧版缺门中心、当前源码不符与6黑图的严格拒绝。当前通过只来自两组v3，不合并旧版结果提高样本数。
