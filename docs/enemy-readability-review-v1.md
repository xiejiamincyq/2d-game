# 普通敌人连续受击可读性修复

2026-10-07，分支 `5分钟超载`，基线 `e3450f2`。只修现有七类 Enemy 的受击反馈；没有新素材、新玩法或许可证状态提升。音效候选来源仍见[原记录](audio/overdrive-bone-breaking-source-v1.md)，不按作者或同名猜测原文件。

## 原因与改动

上一轮组合实跑图发现普通敌人白色剪影。代码中每次有效伤害重置80ms，shader强度1使不透明核心RGB全白；不据此断言某个自然实例的持续时间或具体伤害来源。新测试在原实现真实失败：kind0/frame0/flash1，退出1，非解析错误。生产仅新增 `HIT_FLASH_AMOUNT=0.35` 并替换强度值，沿用已批准Boss方案；shader、位图、计时、Alpha赋值、事件、伤害、移动、物理圈和死亡逻辑不改。

## 验证

- `EnemyReadabilityTest`：七类各120次实际0.1激光伤害、累计HP/事件、80ms前后边界、无效/无敌拒伤、致死幂等和节点回收，共2576断言，修后退出0。Alpha断言仅检查节点属性，不证明合成画面逐像素Alpha。
- 既有Dasher/六类静态图测试保留即时反馈/清除/朝向/动画/碰撞检查，即时强度从旧全白改为精确0.35；新套件已进入严格runner。
- 最终全门实际退出0：72 Godot套件173350断言、33 Python套件238测试。runner检查每个引擎日志、stdout、stderr及唯一通过标记，不忽略错误/泄漏。台账结构校验退出0，不等于美术/法律批准。
- 原生Vulkan/Forward+ 1280×720组件对照：七类、左右两向，idle/single/continuous/recovered共8原PNG。最终before/after-v5各79选定来源，彼此只有Enemy改变，after全部与当前对应文件一致。1680锚定显示记录除flash_amount外完全相同；idle/recovered原始像素相同。单次与连续受击每个64px中心ROI近白像素均下降超过95%；连续总量28393→2。该ROI不覆盖整张角色，也不测逐像素角色Alpha。
- 已实际看两份连续受击原图及单次对照：修后能保留配色、深色轮廓和内部形状。锚定夹具关闭自动处理，调用真实take_damage/视觉运动函数，恢复时显式推进timer；不将其称为真实物理运动、自然密集战斗或整局验收。
- 原20个用户脏路径哈希保护检查无变化；不暂存这些文件，也不触碰两个旧perf未跟踪文件。

## 失败保留与证据范围

渲染辅助v1把输出目录误当资源，v2缺Main入口而import报错（即便退出0仍被三路门拒绝）。v3手动调用物理时受引擎时步影响，1680位置不匹配，被比较拒绝；v4固定60步后字段匹配，但实际图中演员发生位移、原中心ROI不再对应，不能用它的连续ROI零值证明改善。以上原输出均保留，最终v5改为明确锚定视觉组件并实际查图；不改生产移动逻辑、不倒退工作树或覆盖旧记录。

[证据包](enemy-readability-evidence-v1.zip)包含最终8原图、两完整组件记录、79项来源哈希表、选定源码、红绿/全门/失败日志及辅助脚本，附成员索引。不是完整项目、原生整局录像或EXE；中间失败渲染图仍在本机诊断目录，不全收入精选包。[机器摘要](enemy-readability-summary-v1.json)记录实际校验与包hash。

初次封包误收仍在写入的封包日志（归档时为空）；该旧包及摘要移动到诊断目录保留，最终封包排除自身日志，重新核验成员和当前原路径哈希。
