# Phase 6.2 密集战斗性能与资源回收报告

日期：2026-07-26

环境：Godot 4.7 stable，Windows，无界面测试模式

入口：`res://scripts/tests/PerformanceTest.gd`

## 压力范围

- 250 个终局波次强度敌人及 WaveDirector 活跃注册表；
- 四架无人机连续索敌 300 帧；
- 五个传送门各生成 50 个敌人，分别以 30/60/120 Hz 推进；
- Boss 最高密度 `broken_ring` 弹幕及自然销毁；
- 500 次/类型的火花、碎片、圆环和残影请求；
- 100 次普通命中/击杀提示、400 次 Boss 音频提示。

时间值仅用于同一机器上的前后对比，不作为跨机器硬门槛。自动门禁检查调用次数、生成结果、容量和释放后的状态。

## 测量结果

| 项目 | 结果 |
|---|---:|
| 活跃敌人注册表 1000 次读取 | `0.103–0.105ms` |
| 四无人机 300 帧索敌 | `65.912–70.464ms` |
| 五门生成 250 敌人（30 Hz） | `8.313–9.993ms` |
| 五门生成 250 敌人（60 Hz） | `9.639–11.046ms` |
| 五门生成 250 敌人（120 Hz） | `14.170–16.618ms` |
| 30/60/120 Hz 最终生成数 | `250 / 250 / 250` |
| 压力期间节点数 | `665` |
| AudioStreamPlayer 数 | `17`（固定） |

不同 Hz 的传送门总耗时包含不同数量的测试循环调用，因此这里只比较生成结果与回收状态；三档最终数量一致，门、队列和计时器均归零。

## 已证实并修复的问题

1. 四架无人机原本每帧分别调用一次敌人提供器并复制注册表。300 帧测试记录为 `1200` 次；改为同帧共享快照后为 `300` 次，消除 75% 的重复读取与数组复制。
2. Boss 弹幕自然离树时没有从 `_spawned_projectiles` 移除，长阶段内追踪数组会持续增长。现在在弹幕 `tree_exiting` 时同步移除。
3. 传送门若因场景清理等原因提前离树，正常 `closed` 信号不会触发，遗留队列和计时器。现在正常关闭与异常离树共用幂等清理路径。

## 容量与回收门禁

- Boss 全局弹幕上限保持 `140`，持续生成预算保持 `40/s`；
- VFX 上限保持：火花 `96`、碎片 `48`、圆环 `16`、残影 `24`；过期后全部归零；
- 音频继续使用 16 个一次性 voice 加 1 个激光循环播放器，不因提示次数增长；
- 所有压力夹具释放后，节点计数必须回到测试开始前基线。

## 结论

当前自动压力范围内没有剩余的无界节点、VFX 记录、音频播放器、Boss 弹幕追踪或传送门状态增长。真实 GPU 帧时间和高密度战斗手感仍需在 Windows 图形运行下人工确认，但无需为 Phase 6.2 改变玩法或资源上限。
