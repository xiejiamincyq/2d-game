# 当前旅程真实帧时间采样契约

这是工具与验收边界，不是性能成绩。旧`VerifyChapterPerformance`及F12成绩不能替代当前无尽版本。

`CampaignRuntimeProfile`只观察真实`RenderingServer.frame_post_draw`和场景状态，不改演员、出生、伤害、奖励或时钟。每段COMBAT/BOSS排除最初2秒预热；菜单/暂停不计。记录原始单调微秒、上一回调时间、回调序号、引擎帧号、活敌/弹丸与CPU遥测，慢帧不删。回调序号用于核对采样连续性；不假设引擎process帧与实际渲染回调必定一一对应。

每次恢复采样都产生新的`window_id`并重新预热；暂停后即使仍是同一场遭遇，也不会把暂停时间或恢复前后的密集片段拼在一起。上限60000行，溢出与时钟异常明确失败。正常验收至少1000行，必须同时有战斗和Boss窗口。稠密窗为活敌不少于12，同一窗口连续回调累计至少5秒才标`dense_coverage_available`；没有覆盖不能冒称密集性能通过。回调间隔不等于OS呈现帧或最低硬件FPS。

在采样战斗中不进行GPU截图读回，状态样本明确`image_readback:false`；介绍/回帐篷截图在非战斗窗口。主场景音频节点启用，记录实际驱动；固定步长参数、headless、Dummy音频、缺失数据或读回侵入不算真实性能成绩。CPU Performance监视器更新可能滞后，重复值保留，不作精准逐帧热点归因。

独立Python检查器从原始时间戳复算每行间隔、所有窗口的nearest-rank分位、平均/最大值、慢帧数、人口峰值和连续密集时长，与报告逐一比较，同时校验当前来源、真实退出收据及旅程父子文件。报告最大32MiB，普通旅程状态仍限制4096字节。

运行方式见`docs/testing.md`。`-ProfileMode none`与未采样的固定60Hz阶段只能验证游戏流程；`second`只在第二轮实测；`all`每段均采用真实时钟与默认音频驱动。不要在性能采样中并发跑另一套Godot压力测试。实际本机数据、失败与后续结论另记录，不将此契约或合成单测作为性能证明。
