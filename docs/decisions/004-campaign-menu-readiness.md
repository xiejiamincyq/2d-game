# ADR-004：菜单进度、内容就绪与旧试玩分离

状态：接受。日期：2026-10-09。

六关元数据和永久进度已经存在，但地图/遭遇/Boss闭环尚未完成。不能将原有六波重命名成六关，也不能用旧run存档给新关卡解锁。

## 决定

- `CampaignStartScreen` 只显示目录和进度副本、发请求信号；不存档、不驱动战斗、不修改原模型。
- `set_campaign(progress, ready_chapters: Array[int] = [], storage_notice = "")` 的就绪列表缺省为空。当前Main明确传空；UI外观禁用和实际发信号时的模型检查共同保护入口。
- 每区均可查看简介，但“永久解锁”“内容制作中”是两个独立状态。存档异常也禁止未来章节开局；当前波次试玩仍能进入。
- Main仅只读加载独立的CampaignProgressStore，显示损坏/备份恢复/未来版本提示，不静默写回、降级或覆盖。选择区域、开始旧试玩不会永久开锁。
- 旧试玩开始/继续仍复用原Main状态机与RunSnapshotStore。新开始页退出复用原音频drain流程，而不是直接强制退出。
- 新菜单用局部原生纸面Theme，HUD/暂停/结算暂保持原主题，避免一次视觉升级夹带所有界面和战斗重构。

## 取舍和后续

没有将未制作的章节按钮连到旧波次，也没有为本次菜单改动新增通用导航框架、网络服务或MCP依赖。保留现有GameUI公开的开始/继续面板引用是为旧继续流程测试与诊断使用，并非第二份菜单。

M2.2完成真实首关后，才由已验证的章节调度器开放就绪项并接收chapter_requested。所有角色骨骼未齐备前，仍不能制作新的大型/Boss攻击动画；首关过渡方案必须遵守该门。

验证：CampaignMenuTest、CampaignMenuIntegrationTest、旧UITest/ContinueTest/MainCloseTest；实际Main原生GPU九张截图与110项鼠标/键盘/存档保护检查。没有真人体验验收，也没有六关通关证据。
