# ADR-001：Boss取景与导航参考视区分离

## 状态与日期

2026-10-04，已实现并通过本片技术验证，见[取景结果与残余限制](../boss-camera-framing-v1.md)；不是项目整体或人工视觉签收。取消网页端，由工作区判断。既定纯2D Q版、随机障碍农场、明显轮廓保持不变。

## 问题

[真实基线](../boss-screen-baseline-v1.md)证明：现有相机只跟随玩家，Boss完整身体会与顶部或底部UI相交，也会完全出屏。只约束中心和112px常量不够。Boss、远程小怪以及导演的安全生成区/传送门距离都读取当前呈现相机；平移/缩放若直接回写这些读取，会改变AI/生成规则并引入反馈。

两次基线双方间距可达水平621.45/纵向595.68世界像素，在960×540加顶部/底部UI时无法兼顾全身同时入镜和角色可读尺寸。不得隐藏UI、瞬移/加速Boss、扩大碰撞或将角色缩为小点。

## 决策与空间合同

- 新增独立 `BossCameraFraming`。普通无Boss时不接管，保持Camera2D本地position0、zoom1、内建smoothing8.0和原世界限位。
- Boss可见且完成入口后才接管。用实际可见的六个战斗面板viewport AABB计算保守中间可用带，保留屏幕/UI边距；不用散落的HUD固定高度。
- Solver输入角色世界外框、viewport、实际可用矩形。目标zoom只在0.80—1.00，联合外框可容纳时取最小必要平移/缩放；有限速度平滑响应。玩家84px身体/武器附着偏移使用保守54px半径，不改任何碰撞半径。
- 联合外框不能容纳时，不假装全身可见：仍保证玩家身体/武器在可操作视野，给Boss屏幕边缘方向标记；不把画外Boss瞬移到屏幕。方向标记为奶油底/深青边/珊瑚箭头的非交互Control，不抢鼠标或键盘焦点。
- Boss阶段可用有限世界边缘overscan让边界附近的角色避开UI；物理世界边界不变。结束时恢复原相机四限位。
- `CameraEffects`继续独占offset/rotation与hit-stop反馈；取景只改position/zoom/limits，不在通用反馈模块里塞Boss分支。
- 新增统一 `CombatView` 视区读取接口。无取景接管时保留旧实际相机计算；接管时导航参考视区只由玩家位置、viewport和原世界边界推导，保持1倍视野与8.0参考跟随，**不读取Boss位置、最终取景position/zoom/overscan**。
- Boss、Enemy远程逻辑、WaveDirector安全生成区/portal距离统一读取此导航参考，原48/112px margin及其他机械参数保持。仅一个规范参考入口，不给三个模块各自维护不同坐标规则。
- 导航参考与旧受冲击/限位呈现相机并不完全相同；这是一项明确空间合同变化，不能宣称自然轨迹或AI机械零差异。需要验证“相同玩家参考输入，仅改变呈现相机时，导航区与生成距离不变”。
- 暂停冻结构图、隐藏方向提示；恢复重新显示实际需用提示。Boss死亡/无Boss/清场/结果/重开/退出清理接管与导航引用，恢复默认相机；存档格式不改变，继续从既有稳定边界恢复普通镜头。

## 验证门槛

1. 在真实Main建造的Camera2D、GameUI、Boss/玩家夹具中先复现可行近距Boss被实际UI遮挡，退出1而非解析器错误；夹具不创建真实存档、使用明确组件状态，不能冒称自然输入。
2. 四尺寸960×540、1280×720、1920×1080、2560×1080；上下左右、世界边缘、可行与不可行间距、隐藏UI/连击变化、受击镜头；按实际viewport投影检查身体、UI及方向标记。
3. 原Boss/Enemy/Wave/Portal/Movement/Continue/State测试与新增空间隔离/生命周期断言；不能为了候选修改伤害、速度、射击方向或降低既有断言。
4. 修前/后原始组件图、动态位置/缩放记录、明确不可行时的提示；再做当前源码绑定的真实自然整局，缺景/失败保留，不挑结果冒称全景或配对改善。
5. 完整回归、独立审查、聚焦提交/推送当前分支与Gmail阶段报告。人工手感、最低硬件、权利来源及S2—S5其余范围不能代签。

## 未选择的方案

- 改大Boss安全margin：无法处理追赶延迟和屏幕边缘UI，且会改导航。
- 镜头只追Boss：丢失玩家操作视野，仍可能与导航形成循环。
- HUD淡化/角色置顶HUD：损伤状态可读性及交互，不是取景修复。
- 无限缩放全地图：违背既定地图不能一览无余和Q版可读性。
- 只改Boss读相机、不管远程敌人/导演：留下间接机制耦合，因此采用共同视区接口。
